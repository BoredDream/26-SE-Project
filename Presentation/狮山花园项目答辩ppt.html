项目背景与意义
为什么做 · 解决什么 · 创新点何在
BACKGROUND
「樱花开了？
我昨天刚去
都凋谢了……」
— 每年都在发生的遗憾
三个尚未被解决的校园痛点
1
不知道在哪里 校园植物分布没有统一信息渠道
2
不知道现在开没开 花期每年偏差 1–2 周，历史数据参考性有限
3
错过了才知道 只能从朋友圈事后得知，已无缘相见
GOAL & INNOVATION
项目目标 +
六大核心创新点
打造一款校园专属的花卉打卡小程序「狮山花园」，通过众包打卡实时维护花期状态，让每一位同学都能在最美的时刻赶到最美的地点。
🔁
众包驱动的花期数据飞轮
打卡即数据，无需专职运营，用户越多数据越准 → 越多人用 → 自驱飞轮
🗺️
花期状态实时可视化地图
花点颜色实时反映花苞 / 盛开 / 凋谢 / 休眠四种状态，支持按花期筛选
🏆
游戏化激励体系
成就花圃 + 金 / 银盆栽分级 + 称号系统（花卉观察员、探花使等）
📍
GPS 校验与品质分级
150m 内打卡获金色盆栽，未验证位置获银色盆栽，激励真实到访
🔔
花开主动通知
用户订阅某个花点后，花期到达时通过微信订阅消息自动提醒
🛡️
AI 内容审核
接入微信内容安全 API，自动过滤违规内容，降低人工成本

BACKEND IMPLEMENTATION
后端核心实现 · Flask
🔐
用户认证
JWT
支持账号密码与微信 code 双通道登录，统一下发 JWT Token，所有受保护接口需携带 Authorization: Bearer
🗄
数据建模
11 TABLES
11 张业务表覆盖用户、花卉、地点、打卡、评论、成就、称号等；FlowerPlace 作为核心关联实体
📍
GPS 校验接口
150m
计算用户与花点的实际距离，≤150m 自动通过获金色盆栽，其余降级为银色盆栽
🗳
花期投票算法
CROWDSOURCING
24 小时内同一地点收到 ≥3 条相同花期、且占比 ≥60%，系统自动更新花期状态
📸
打卡系统
UPLOAD
发布、点赞、评论、列表的完整 CRUD；图片自动生成三级分辨率（缩略 / 中图 / 原图）
🏆
成就与称号
GAMIFY
成就解锁判定、称号佩戴切换、自动落库；触发条件可配置，便于扩展
🔔
订阅消息推送
WECHAT
花开提醒、称号解锁两类模板消息；Redis 防重避免重复推送同一用户同一花点
🛡
AI 内容审核
SAFETY
接入微信内容安全 API，对上传图片与文字进行自动审核，违规内容直接拦截
FRONTEND & CROSS-PLATFORM
前端 H5 与跨端小程序
💻
Vue 3 H5 端
FRONTEND/
  • 8 个视图页面：Home / Map / Checkin / Garden(3D) / Profile / Login / Register / UserDetail
  • 4 个 Pinia 模块：auth、checkin、location、achievement，集中管理跨页面状态
  • 腾讯地图集成：花点标记、状态颜色映射、筛选组件、热力图叠加层
  • Three.js 花圃：打卡新花种后生成 3D 盆栽生长动画
  • API 客户端封装：统一 /v1/... 接口，自动携带 Token，失败回退 Mock
  • 路由守卫：基于 localStorage 的鉴权拦截，强制登录态访问
📱
uni-app 微信小程序端
FRONTEND-UNI/
  • 跨端适配：通过 uni-app 一套代码同步发布到 H5 与微信小程序
  • 核心流程闭环：登录 → 浏览地图 → 打卡 → 点赞 / 评论 → 个人花圃
  • 原生地图组件：使用微信小程序内置 map 组件，性能更优
  • 微信能力：wx.getLocation 静默定位、订阅消息授权
  • 自定义 tabBar：中央凸起打卡按钮，匹配小程序原生设计语言
  • UI 一致性：与 H5 共享设计 token，保证双端视觉统一
— 本项目为从零开发，非二次开发，所有代码均为小组原创 —
