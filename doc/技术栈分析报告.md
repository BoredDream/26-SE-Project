# 狮山花园 技术栈分析报告

> 项目定位：面向校园师生的花卉地图打卡 Web 应用。用户在地图上查看花卉分布、发布打卡帖子、查看动态、积累等级与成就。
> 架构形态：**Vue 3 单页前端 + Flask REST API 后端**，前后端分离。

---

## 一、总览

| 层次 | 技术选型 |
|------|----------|
| 前端框架 | Vue 3（Composition API） |
| 前端构建 | Vite 7 + TypeScript 5.9 |
| 状态管理 | Pinia 3 |
| 路由 | Vue Router 4 |
| 地图 SDK | 高德地图 JSAPI |
| 端到端测试 | Playwright |
| 后端框架 | Flask + Flask-RESTful |
| ORM / 迁移 | SQLAlchemy + Flask-Migrate（Alembic） |
| 认证 | flask-jwt-extended（JWT） |
| 数据库 | SQLite（默认），驱动支持 MySQL（PyMySQL） |

---

## 二、前端技术栈

### 核心依赖

| 依赖 | 版本 | 作用 |
|------|------|------|
| `vue` | ^3.5.29 | 视图框架，Composition API |
| `vue-router` | ^4.6.4 | 单页路由，带认证守卫 |
| `pinia` | ^3.0.4 | 状态管理（auth / location / checkin / achievement） |
| `@amap/amap-jsapi-loader` | ^1.0.1 | 高德地图 SDK 加载器 |
| `@amap/amap-jsapi-types` | ^0.0.15 | 高德地图类型定义 |
| `three` | ^0.183.2 | **未实际使用**（源码仅有同名 CSS 类，可考虑移除） |

### 构建与开发工具

- **Vite 7** — 开发服务器（默认 5173）与生产构建，`@` 别名指向 `./src`。
- **TypeScript 5.9 + vue-tsc** — 类型检查（`npm run type-check`）。
- **sass-embedded** — SCSS 样式编译。
- **vite-plugin-vue-devtools** — 开发期调试。
- **Node 版本要求**：`^20.19.0 || >=22.12.0`。

### 应用结构

- `src/views/` — 页面：登录、首页、地图、打卡、花园/成就、个人中心等。
- `src/components/` — 复用组件：底部导航、花卉搜索建议。
- `src/services/api.ts` — 集中式 API 客户端（封装 `fetch`，自动携带 JWT），基础 URL 硬编码、路径前缀 `/v1/...`。
- `src/services/mockData.ts` — Mock 数据，配合**降级策略**：API 失败时 stores 自动回退，保证页面可渲染。
- `src/stores/` — Pinia 仓库。

### 测试

- **Playwright E2E**，固定移动端 H5 视口（390×844），单 worker 串行。
- 依赖 Mock 降级，**无需后端即可运行**；`webServer` 自动拉起 `npm run dev`。
- 截图作为视觉留档入库；选择器直接对应源码类名。

## 三、后端技术栈

### 核心依赖

| 依赖 | 作用 |
|------|------|
| `Flask` | Web 应用框架（单体应用，入口 `app.py`） |
| `Flask-RESTful` | REST 资源类组织（`routes.py`，路径前缀 `/api/...`） |
| `Flask-SQLAlchemy` | ORM |
| `Flask-Migrate` | 数据库迁移（Alembic） |
| `Flask-JWT-Extended` | JWT 认证，登录/注册下发 Token |
| `Flask-CORS` | 跨域支持 |
| `Werkzeug` | WSGI 基础库、文件上传处理 |
| `PyMySQL` | MySQL 驱动（当前默认仍用 SQLite） |
| `python-dotenv` | 加载 `.env` 配置 |

### 数据模型

- 实体：`User`、`Flower`、`Place`、`FlowerPlace`（关联表）、`Checkin`、`Achievement`、`Title`。
- **`FlowerPlace` 为核心关联实体**，连接 `Flower` 与 `Place`；打卡记录绑定到 `FlowerPlace`。
- 花期枚举：`dormant` / `budding` / `blooming` / `withering`。

### 其它

- 默认数据库 SQLite（`sqlite:///flower.db`）；`flower_db.sqlite` 仍被 git 跟踪，本地运行会产生二进制 diff。
- 图片上传至 `backend/uploads/`，经 `/uploads/<filename>` 访问。

## 四、关键风险与注意事项

1. **前后端 API 不兼容（最高优先级）**
   - 前端请求 `/v1/...`，后端提供 `/api/...`；登录参数（微信 `code` vs `username/password`）、打卡绑定字段（`location_id` vs `flower_place_id`）均不一致。
   - 结果：前端直连后端会全部 404/参数错配，stores 全量回退到 Mock 数据。**对接前必须先对齐协议。**

2. **登录为演示模式** — 前端无真实表单，仅"演示模式"按钮，生成假 Token 并写入 Mock 用户。

3. **测试覆盖不均衡** — 仅有前端 E2E，后端无单元/集成测试，全项目无 lint 配置。

4. **文档与实现脱节** — 根目录 `README.md` 描述的是早期"小程序 + Node/Express + MySQL + 腾讯地图"方案，与现状（Vue 3 + Flask + SQLite + 高德地图）不符；`doc/API.md`、`Frontend/API_DOC.md`、`backend/后端设计.md` 三份接口文档互不一致。

5. **冗余依赖** — `three` / `@types/three` 未使用，可清理。

## 五、技术选型评价（简评）

- **前端**：版本新（Vue 3.5 / Vite 7 / TS 5.9），工具链现代，Mock 降级设计利于前端独立开发与测试，工程化程度较好。
- **后端**：Flask 全家桶组合标准、轻量，适合中小型项目与快速迭代；当前用 SQLite 便于开发，已预留 MySQL 驱动可平滑迁移生产。
- **主要短板**：前后端契约未对齐 + 后端缺测试，是当前阻碍真实联调与上线的核心问题，应优先统一 API 规范并补充后端测试。
